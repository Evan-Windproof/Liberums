# 独立用户地址空间

## 相同虚拟地址，不同物理页

一个指针数值不是全机器唯一的物理资源身份。CPU 依据当前 CR3 的页目录，把线性地址翻译成物理页。
因此 A 与 B 可以使用相同虚拟地址，又看不到彼此的数据：

```text
域 A，CR3_A: 0x08001000 -> 物理页 P_A（aaaaaaaa）
域 B，CR3_B: 0x08001000 -> 物理页 P_B（bbbbbbbb）
P_A != P_B
```

每次进入域前写入其 CR3，切回调度者后恢复原内核 CR3。
本阶段没有 global page 或 SMP，CR3 切换清除旧的非全局翻译；销毁前不允许该页目录仍处于活动状态。

## 固定用户布局

| 虚拟范围 | 内容 | 用户权限 |
| --- | --- | --- |
| 0x08000000..0x08000fff | 受信测试代码映像的私有副本 | 读，不能写 |
| 0x08001000..0x08001fff | 私有数据 | 读写 |
| 0x08002000..0x08002fff | 私有用户栈 | 读写 |
| 0x08003000 之后 | 未映射 | 无 |
| 0x08400000（仅 A） | A 数据页的显式探测别名 | 读写 |
| 0x08800000（仅 B） | B 数据页的显式探测别名 | 读写 |

两个别名用于实际的双向越界实验：A 访问 0x08800000 会 #PF，B 访问 0x08400000 也会 #PF。
普通数据页仍在相同虚拟地址，GDB 检查其物理目标不同；不是让两个域共享一个可写用户页。

低 64 MiB 沿用内核 identity mapping，但 PDE 的 U/S=0，所以 CPL 3 不能用原始物理数值绕过隔离。
代码、页表、固件和引导信息在这里都不对用户开放。测试还让用户尝试读取另一域数据页的
原始物理地址、写自己的页目录地址，确认它们被 supervisor 权限阻止。
这些地址仅为受控诊断标量，不是授权句柄，也不会被系统调用当作映射请求处理。

## 六页的生命周期

每域申请：页目录、普通用户页表、探测页表、代码页、数据页、栈页，共六页。
代码页也独立复制，简化本阶段的所有权与回收检查。每域另外有一个静态的 supervisor 内核栈，
属于内核 ELF 的永久保留区，不计入六页动态资源。

```text
申请 -> 清零 -> 复制映像/建立固定 PTE -> 标记 live
        | 申请中途失败
        +-> 清零已申请页 -> 全部归还 -> 返回失败

EXITED/FAULTED -> 切回内核 CR3 和调度栈
              -> 清除域目录/页表及所有别名
              -> 清零所有 backing pages
              -> 归还页追踪模块，标记非 live
```

映射只由创建函数使用自己取得的页建立，用户不能提交任意 PFN。
物理分配器不会返回 KERNEL/RESERVED 页，两个域取得的十二页必须彼此不同。
测试在释放后读取实际页内容、页状态和空闲总数，再重新创建一轮检查旧数据没有残留。

故障域被立即标为 FAULTED，不再执行；物理资源延迟到本轮所有域结束后统一回收。
这样不会在异常 handler 正在使用其内核控制路径时释放活动资源。

## 权限实际怎样生效

PDE 和 PTE 都必须允许 user，CPL 3 才能访问；任何一级 supervisor 都会拒绝用户。
用户代码 PTE=present+user，数据/栈=present+user+writable；用户页表本身位于低端 supervisor 区。
内核代码/常量继续依靠原 CR0.WP 和只读 PTE 保护。

普通 i686 非 PAE 分页没有 NX：可写用户数据/栈仍可能执行，不能宣称完整 W^X。
本阶段证明的是访问特权和写保护，没有解决代码完整性、侧信道或可信执行。

## 与 Exokernel 的关系

域中的六页列表是内核内部的生命周期记录，防止遗漏和重复释放。
它没有可委托权利、授权句柄、代数检查或可见撤销，不是 Phase 4 的 Resource Ownership / Secure Bindings。
用户目前只能 yield/exit/log_char，没有选择物理页、共享页或更换映射的接口。
未来 LibOS 的堆、缓存、虚拟地址策略需要在受检查的资源接口之上自主实现。
当前固定布局只是教学与安全实验的起点。
