# 理解物理资源所有权

## 页号不是权限

物理页编号 PFN 是物理地址除以 4096。例如 PFN 0x200 表示地址 0x200000 的页。
编号只是身份信息；B 知道 A 的 PFN，并不意味着可以取得或映射它。
用户不能直接写 PTE，内核也不会把一个整数物理地址当成权限凭证。

原 `PAGE_ALLOCATED` 只表示页已经从早期分配器取出。它不能区分“用于 A 的动态资源”与
“用于 B 的页表”。Phase 4 另外维护 `resource` 表，而不改写 Phase 2 的状态定义。

## 两层记录

| 记录 | 回答的问题 |
| --- | --- |
| 物理页状态 | 该页是否是可用 RAM？是否保留、供内核使用、已被取出？ |
| 资源表 | 哪个域实例独占这页？代数、权限、绑定数是什么？ |

内核/固件/引导页仍由原状态表保护，不能成为用户动态资源。
claim_specific 只对 PAGE_FREE 成功，不能重复取得 PAGE_ALLOCATED 页；六页启动基础和动态页表也不例外。

每个活跃资源的身份由表索引和代数组成，记录物理页、owner_id、owner_epoch、rights、references 和绑定列表。
owner_epoch 区分同一个域槽位的不同生命期；id=1 的下一轮域不是上一轮域的同一个主体。

资源 FREE 表示槽位没有有效授权，不代表历史 physical_address 字段指向的页永远空闲。
该字段仅用于诊断，不能跳过状态/代数校验。活跃 OWNED 记录才是当前所有权事实。

## 状态变化

```text
FREE --取得并清零物理页--> OWNED
OWNED --撤销、清零、归还--> RECLAIMING --> FREE
OWNED --转移预检通过--> RECLAIMING --撤销并清零--> OWNED（新所有者、新代数）
```

RECLAIMING 阶段拒绝句柄解析，旧所有者不能创建新绑定。没有 TRANSFER_PENDING：
当前转移在一个系统调用内同步完成，不等待另一个域执行代码或确认。
中断关闭、没有 SMP、操作中不 yield，保证检查和提交之间没有另一个用户域并发修改状态。

一页最多有一个有效所有者。四个绑定可以是同一所有者地址空间中的多个别名，不是跨域共享。

## 代数为什么不能回绕

用户保存的句柄可能比资源活得更久。释放后槽位会复用，若只检查 index，旧句柄会错误地指向新页。
本实现使用完整 32 位 generation，claim 和 transfer 都需要前进到下一代。

- 当前为 0 时，第一次分配为 1；0 永远不是有效代数。
- 到 UINT32_MAX 时，已有资源仍可合法使用和释放。
- 此时不能再转移；释放后该槽永久不再复用。
- 没有截断成 16 位，也没有把溢出后的零当作新授权。

域实例计数 epoch 同样不会回绕：耗尽时严格停止，而不是重新使用旧身份。

## 权限是服务器记录

句柄包含 index/generation；域身份来自已验证的陷入现场，权限来自内核表。
用户自行在寄存器里构造更大的权限数字不会修改授权。
初始 claim 可选择 RESOURCE_ALL 的子集；必须包含 READ。转移只能进一步缩减权限。
没有密码学令牌，也不依赖句柄难以猜测：即使完整知道 A 的句柄，B 也会因身份不符被拒绝。

## 独占转移的提交顺序

1. 校验发送方句柄、TRANSFER 权限、OWNED 状态。
2. 校验目标域存活、不是自己、容量足够、收件槽空闲，检查权限子集和下一代可用。
3. 进入 RECLAIMING，撤销发送方所有别名并完成 TLB 同步。
4. 清零整页，而不是只清第一个字。
5. 更新所有者 id/epoch、代数和缩减后的权限，调整两域计数。
6. 将新句柄放入目标收件槽，恢复 OWNED。

所有普通失败条件都在第 3 步之前检查，因此配额不足、收件槽满、权限或代数错误会保留原
所有权、映射、引用数和数据。提交阶段不再分配物理页/页表，不存在需要回滚的可预期分配失败。
如果内部 PTE 与记录矛盾，则 Panic，不能带着不确定访问权限继续运行。

目标通过 page_receive 取得通知。所有权在转移调用成功时已经更换，receive 只是取出通知，
不是在两个有效所有者之间切换的第二个授权步骤。旧通知在再次转移、释放或域退出时清除。

## 生命周期清理

显式 release 会撤销该资源的全部别名、清零，再归还物理分配器。重复 release 返回 ESTALE。
正常退出和用户异常都在回到可信调度栈、恢复内核 CR3 后调用 resource_cleanup。
即使该资源不授予用户 RELEASE 权限，域生命期结束时内核仍会回收它。

转移给 B 的页已经不是 A 的资源，因此 A 故障后的清理不能释放 B 的页。
只有清除所有用户访问路径后，才允许物理页成为 FREE。
这依赖本阶段的单 CPU、无 global page、无 DMA 授权模型；不能直接泛化为多核或设备撤销保证。
